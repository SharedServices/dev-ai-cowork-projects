# Remittance EventsSource application name: `snowdrop-remittance` (kebab-case `SourceApplication` string; see `Identifiers.RemittanceApplication` in `Snowdrop.Remittance.Runtime/Eventing/Identifiers.cs`. The CLR namespace for the event classes themselves is `Snowdrop.Remittance.Events`.)---## Stream FormatsEach stream is identified as `ApplicationName->Partition->EntityTypeName->EntityId`, built via `EventStreamIdentifier.Create(...)` in `Identifiers.ForRemittance` (`src/Snowdrop.Remittance.Runtime/Eventing/Identifiers.cs`).| Stream | Format ||--------|--------|| Remittance | `snowdrop-remittance->{OrganizationId}->remittance->{RemittanceId}` |**Notes on stream IDs:**- Unlike sibling services (e.g. Payers, Remittance Processing), this repo defines exactly **one** entity type constant (`Identifiers.RemittanceEntity = "remittance"`) and exactly one stream shape. Every event in `Snowdrop.Remittance.Model/Events` is written to this single Remittance stream, keyed by `RemittanceId`, partitioned by `OrganizationId`.- `RemittanceEventStore` (`src/Snowdrop.Remittance.Runtime/Eventing/RemittanceEventStore.cs`) routes each read/write to one of two physical Cosmos containers ("auto" vs "manual"), selected per call by `RemittanceEventContainerManager.IsManual(organizationId, remittanceId)`. This is a storage-routing concern only — it does not change the stream identifier shape above, and both containers hold the same single stream type.- The `Snowdrop.Remittance.Model/Events` folder is flat (no subfolders); the categories below are inferred from naming convention and purpose rather than from a folder structure.---## Base Classes### `IRemittanceEvent` (`IRemittanceEvent.cs`)Marker **interface**, not an abstract base class. Provides `Guid RemittanceId { get; set; }`. Almost all events in this folder implement it.**Exceptions — events that do NOT implement `IRemittanceEvent`:**- `RemittancePerClaimEobRemittancePdfAttachmentsUpdated` — declares `RemittanceId` directly as a plain property, no interface.- `RemittanceRegenerateClaimEobsEvent` — declares `RemittanceId` directly as a plain property, no interface.**Naming/filename quirks worth flagging:**- `RamittancePostingStatusUpdated.cs` is a misspelled filename (missing "e" in "Remittance"); the class inside is correctly named `RemittancePostingStatusUpdated`.- `RemittanceRegenerateEobsEvent.cs` does not contain a class named `RemittanceRegenerateEobsEvent` — it actually declares `RemittanceRegenerateRemittanceEobEvent : IRemittanceEvent`. Documented below under its actual class name.No `OrderedCollectionItemUpdatedEventBase`/`OrderedCollectionOrderUpdatedEventBase` pattern (as used in Payers) appears anywhere in this folder — none of the model types implement `IOrderedCollectionItem`, and there are no ordered-collection or collection-reordering events. Collections referenced by events (e.g. `ClaimIdentifiers`, `Services`, `Adjustments`) are plain `List<T>` properties replaced wholesale, not individually keyed/ordered items.---## Model Types###
