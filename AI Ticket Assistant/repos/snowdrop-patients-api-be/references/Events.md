# Patient Events## Stream FormatAll events are persisted to the CosmosDB event store under the stream identifier:```Snowdrop.Patients->{OrganizationId}->Snowdrop.Patients.Patient->{PatientId}```Consumers receive events via CosmosDB Change Feed, filtered by entity type `Snowdrop.Patients.Patient` and the event class name.  Namespaces: `Snowdrop.Patients.Events`, `Snowdrop.Patients.Events.PersonalContacts`, `Snowdrop.Patients.Events.System`---## Base Class### `PatientEvent` _(abstract)_Base class for the majority of patient events. Implements `IPatientIdentifiable`.| Property | Type | Description ||---|---|---|| `PatientId` | `Guid` | Unique identifier of the patient. |---## Base Class Serialisation Patterns### `OrderableItemUpdatedEventBase<TKey, TItem>` and `OrderedCollectionItemUpdatedEventBase<TKey, TItem>`Used by single-item collection mutation events (phone, fax, email, address, location, personal contact, probable duplicate, merge source). The item is serialised as a dictionary keyed by its ID under the subclass's chosen JSON property name.**Effective JSON shape:**```json{  "PatientId": "<guid>",  "Addresses": {    "<AddressId>": { ...Address properties... }  }}```### `OrderedCollectionOrderUpdatedEventBase<TKey>` / `OrderableCollectionOrderedEventBase<TKey>`Used by collection order events. Carries `TKey[] Order` serialised under the subclass's chosen JSON property name.**Effective JSON shape:**```json{  "PatientId": "<guid>",  "Addresses": {    "order": ["<guid1>", "<guid2>", ...]  }}```---## Enums### `StatusType`| Value | Int | Description ||---|---|---|| `Active` | 0 | Patient is active. || `Inactive` | 1 | Patient is inactive. || `Deceased` | 2 | Patient is deceased. ||
